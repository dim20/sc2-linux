# v0.7.3-wifi — WiFi on the S905X4/SC2

The optional WiFi bring-up. The board's soldered module is a **Realtek
RTL8822CS** over SDIO (`024c:c822`); v0.7.2 had no client driver. This
release ships the stack as six loadable modules, so the kernel Image stays
small and the modules can be updated with the image that matches them.

**Status: released 2026-10-29.** Built and manifest-checked; a candidate
built from the same tree was stick-booted, installed to the eMMC and
cold-booted standalone, with the 24-check smoke test passing each time.

## What changed since v0.7.2-sc2

### 1. The SDIO host runs its initial scan

The vendor's `meson-gx-mmc` set `mmc->rescan_entered = 1` for SDIO hosts.
`aml_wifi` powers the chip, but nothing rescanned the bus afterwards, so
`/sys/bus/sdio/devices/` stayed empty. `patches/0011-sdio-run-initial-rescan.patch`
sets it to zero. The card then enumerates as:

    mmc1: new ultra high speed SDR104 SDIO card at address 0001

### 2. The RTL8822CS stack ships as modules

The vendor 5.4 tree's `rtw88` driver is PCIe-only. The SDIO driver comes
from the lwfinger `rtw88` backport, trimmed to the four modules the 8822CS
needs. The image carries six stripped modules under
`/lib/modules/<uname -r>/extra/`:

- `mac80211.ko` and `ccm.ko` from the vendor tree;
- `rtw_core.ko`, `rtw_sdio.ko`, `rtw_8822c.ko`, `rtw_8822cs.ko` from the
  backport.

`/etc/modules-load.d/rtw88.conf` loads them at boot. The driver loads
firmware 9.9.6 (WOW 9.4) and creates `wlan0`.

### 3. WiFi userspace

`wpa_supplicant@wlan0.service` is enabled and the generic
`wpa_supplicant.service` is masked, so two supplicants cannot contend for
the interface. `/etc/wpa_supplicant/wpa_supplicant-wlan0.conf` is the
vendor's symlink to `/root/wpa_supplicant.conf`; the image ships a
**credential-free template** there. `systemd-networkd` applies
`/etc/systemd/network/20-wlan0.network` and does DHCP with
`RouteMetric=4096`, so Ethernet remains the preferred default route.

### 4. Installer and smoke-test hash

`install-to-emmc.sh` and `smoke-test.sh` still defaulted to the v0.7.2
kernel hash. They now expect `e8e4dda1…`. Without this, the installer
would have refused the new kernel.

---

## What did not change

- The text console on HDMI and serial, the HDMI audio service, the clock
  fallback, the hostname fix, the eMMC installer and the 24-check smoke
  test.
- The `sc2-kernel` package is still Image-only. The WiFi modules ship in
  the OS image, not in the package. A kernel-package update must be paired
  with the matching module set from the same release.
- The device tree is unchanged.

## What is still broken, or not yet proven

- **No WiFi credentials are shipped.** The template is deliberately empty.
  Add a network block with `wpa_passphrase`, then restart
  `wpa_supplicant@wlan0`.
- **Association was not tested on the release image itself**, because the
  image ships no credentials. Association to `TP-Link_8860` with
  `PTK=CCMP GTK=TKIP`, DHCP, ping and `iw scan` were verified on the
  development box with the same stack.
- **Bluetooth is unverified.** There is no `/sys/class/bluetooth` device
  and no Bluetooth tooling.
- The vendor's 6.18 module tree is still in the rootfs. It is for a
  different kernel and cannot load; it is recorded in
  `manifest/vendor-leftovers.txt`.
